# CMaS 2017 — paper-to-code audit (paper 2 comparator)

## Bibliographic identity

- **Algorithm:** CMaS — Cost-Makespan aware Scheduling, with deadline-based task reassignment
- **Paper:** Xuan-Qui Pham, Nguyen Doan Man, Nguyen Dao Tan Tri, Ngo Quang Thai, Eui-Nam Huh, *A cost- and
  performance-effective approach for task scheduling based on collaboration between cloud and fog computing*
- **Venue:** International Journal of Distributed Sensor Networks 13(11), 2017
- **DOI:** `10.1177/1550147717742073`
- **Primary source audited:** complete user-supplied PDF (16 pages)

## Original problem

Workflow (DAG) scheduling on a fixed cloud–fog processor graph. The node-selection phase maximizes a
cost–time trade-off; a second phase reassigns critical-path tasks to meet a user deadline "with the possibly
lowest amount of the monetary cost for cloud resources". It is deadline-aware and cost-aware, but not a pure
cost minimization.

## Original resource and monetary model

- Fixed sets of fog nodes (owned by the customer) and cloud nodes (rented); each processor has rate `p_i` and
  link bandwidth `bw_i`.
- Insertion-based EST/EFT (Condition 1, Eqs. 7–9).
- Communication Eq. (5) includes data already stored at the source node (`d_i^m`), zero on the same node.
- Cost Eq. (10)–(14): on a cloud node, processing + storage + memory + communication cost of data coming
  from cloud nodes; on a fog node, only the communication cost of data coming from cloud nodes.

## Algorithm (as published)

1. **Priority** (Eqs. 1–3): upward rank with average execution time over all nodes and average communication
   time `c_ij / mean bw`.
2. **Node selection** (Algorithm 1): in priority order, assign each task to the node maximizing
   `U(v_i, P_n) = [min_k cost(v_i, P_k) / cost(v_i, P_n)] × [min_k EFT(v_i, P_k) / EFT(v_i, P_n)]` (Eq. 15).
3. **Deadline-based reassignment** (Algorithm 2), repeated:
   - find the critical path CP of the current schedule;
   - `distance = (old_makespan − deadline) / |CP|`;
   - for each critical task, `subdeadline = AFT − distance`;
   - if `subdeadline ≥ 0`: candidates = nodes with `EFT ≤ subdeadline`; pick max `U` among them, else min EFT;
   - re-schedule the non-critical tasks (line 24);
   - stop when `makespan ≤ deadline` or the makespan no longer improves.

Deterministic.

## Faithfulness classification

**MINOR MODEL ADAPTATION** for the resource and timing model, which is native: fixed fog/cloud nodes and
insertion. Three specification gaps (critical path, line 24, return rule) are resolved above and must be
reported.

Its objective is a cost–time trade-off rather than strict cost minimization. In paper 2 it is the native
IoT–Fog–Cloud cost-aware, deadline-aware baseline, not a pure cost-minimization competitor.

## Complexity

The paper gives no explicit bound. Node selection is HEFT-like, `O(n·m·k)` with insertion. Each reassignment
round costs about one full rebuild, and the number of rounds is bounded by the stop rule.

## Observed behaviour on IFC v1 (diagnosed 9 November 2026)

On the 594-instance expansion sample, CMaS meets 0 of 396 tight and moderate deadlines and 102 of 198 relaxed
ones. The deadline misses come from the published method, not from the port:

- Every IFC instance has free IoT economy slots, so `min_k cost = 0` for every task. With the free-resource
  convention above, Eq. (15) gives every priced resource utility 0, and Algorithm 1 places almost every task
  on a free slot. On the dev 60-task instances, the first critical path contains all 60 tasks: the workflow
  is serialized on one slot.
- Algorithm 2 then moves critical-path tasks one sub-deadline at a time. Each round shortens the makespan by
  about 5–10% (dev trace: 3.16e9 → 2.83e9 → 2.72e9 → … µs). The paper's stop rule ("the makespan no longer
  improves") ends the loop at 6–16 rounds, before the deadline, well under the 64-round safety cap.
- Typical final makespan on tight and moderate instances: 3.5× D (median); the smallest is 1.6× D.

Any other finite convention for `cost = 0` would be an invented parameter. CMaS is therefore reported as the
native IoT–Fog–Cloud cost-aware baseline, together with this diagnosis, and not as a cost-minimization rival.
