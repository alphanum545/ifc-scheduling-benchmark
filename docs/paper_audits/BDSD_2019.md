# BDSD (Sun, Xiao, Xu, 2019) full-paper audit

## Source

- Ting Sun, Chuangbai Xiao, Xiujie Xu, **"A scheduling algorithm using sub-deadline for workflow applications under budget and deadline constrained"**, *Cluster Computing* 22 (Supplement 3), 5987-5996.
- DOI: `10.1007/s10586-018-1751-9`.
- Full paper reviewed before implementation.

## Suitability for frozen IFC-v1

**Decision: include as a primary comparator with `MINOR_IFC_ADAPTATION`.**

Unlike DB-ACO/DBWS-style cloud algorithms, BDSD does not depend on elastic VM creation, VM boot delays, lease intervals, or hourly billing. The paper defines a bounded heterogeneous system `P={p1,...,pm}`. Every task can be assigned to one of those existing processors, execution time is stored in a task-by-processor matrix, each processor has a unit execution-time price, and task cost is execution time times that processor price. This is structurally compatible with the frozen IFC resource pool and its authoritative per-task compute-cost matrix.

BDSD also takes exactly the two public workflow-level constraints available to our benchmark: budget `C` and deadline `D`.

## Paper mechanism to preserve

### 1. Sub-deadline task ordering — Eq. (12)

For the exit task:

`SDL(exit) = D`

For every other task `ni`:

`SDL(ni) = min_{nk in succ(ni)} [ SDL(nk) - Abar(i,k) - ETmin(nk) ]`

where `Abar(i,k)` is the average communication time and `ETmin(nk)` is the minimum execution time of successor `nk` over all processors.

Tasks are scheduled in ascending `SDL` order.

### 2. Remaining budget — Eq. (13)

Initialize `rb = C`. After selecting processor `pj` for task `ni`:

`rb = rb - c(i,j)`

### 3. Expected reasonable cost — Eq. (14)

If `l` tasks remain unscheduled:

`erc(ni) = rb / l`

This must use exact rational arithmetic in IFC-v1.

### 4. Affordable processor set — Eq. (15)

For current task `ni`, retain processors whose task cost is no greater than `erc(ni)`.

### 5. Processor selection

The printed prose contains an obvious duplicated condition: both numbered selection cases are typeset as `omega_k = empty`, even though they prescribe different actions. The worked example resolves the intended behavior unambiguously:

- when one or more processors satisfy the expected-reasonable-cost filter, choose the processor with the **earliest finish time** among that affordable set;
- when no processor satisfies the filter, choose the **cheapest processor**.

The implementation will follow the worked example and Algorithm 1 semantics, while recording this paper typo explicitly.

### 6. Paper timing model — Eqs. (10)-(11)

BDSD defines append-style processor availability:

`EST(ni,pj) = max(Tavail[j], max_{nk in pred(ni)}(AFT(nk) + communication(nk,ni)))`

with zero communication when parent and child are on the same processor, then:

`EFT(ni,pj) = EST(ni,pj) + execution_time(ni,pj)`.

The paper's selection policy will use this internal timing model. Final benchmark metrics remain independently recomputed by Dataset-v1.

## IFC adaptations

1. **Cost representation.** The paper derives task cost as execution time times processor price. IFC-v1 already materializes the authoritative integer `compute_cost_ncu[task][resource]`; the adapter consumes that exact matrix instead of reconstructing money with floating point.
2. **Communication representation.** Eq. (12) and the paper timing model use an average inter-processor communication value. The adapter obtains the route-aware average communication value from the pinned Dataset graph/rank primitive, but BDSD itself still reasons with a single average edge value as the paper specifies. Final realized route-specific communication is evaluator-only.
3. **Multiple entries/exits.** The paper assumes a single entry and exit and proposes zero-cost dummy nodes otherwise. The frozen dataset is not rewritten. If multiple exit tasks exist, each real exit receives `SDL=D`; deterministic topological tie-breaking preserves precedence without introducing synthetic tasks.
4. **Final measurement.** The paper judges schedule success by its deadline and budget. The benchmark always returns the mapping and lets Dataset-v1 independently report deadline, budget, and joint feasibility; an algorithm-internal paper-success diagnostic is retained only for auditability.
5. **No energy term.** BDSD has no compute/network-energy objective. Energy is evaluator-only and must never alter BDSD's mapping.

These adaptations do not replace BDSD's defining task-priority, budget-distribution, affordability, or processor-selection rules, so the comparator is classified as `MINOR_IFC_ADAPTATION`.

## Determinism and tie handling

The paper does not define ties. IFC-v1 will make ties deterministic without changing primary criteria:

- SDL ties: original topological position, then task ID;
- affordable earliest-finish ties: lower task cost, then resource ID;
- cheapest-fallback ties: earlier paper-model finish time, then resource ID.

BDSD is deterministic and must reject a supplied stochastic seed.

## Complexity

The paper reports `O(n^2 * p)` for `n` tasks and `p` processors. The adapter preserves the same list-scheduling structure and does not add search/metaheuristic loops.

## Implementation acceptance criteria

- Eq. (12) is tested exactly.
- Eq. (14) uses exact `Fraction` arithmetic.
- Non-empty affordable set chooses earliest finish.
- Empty affordable set chooses cheapest processor.
- Energy changes cannot alter BDSD mapping.
- Only materialized IFC resource IDs may be returned.
- Deterministic seed rejection is tested.
- Final metrics come only from the common Dataset evaluator.
