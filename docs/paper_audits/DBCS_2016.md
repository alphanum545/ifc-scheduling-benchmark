# DBCS 2016 — paper-to-code audit

## Bibliographic identity

- **Algorithm:** Deadline–Budget Constrained Scheduling (DBCS)
- **Paper:** Hamid Arabnejad, Jorge G. Barbosa, Radu Prodan, *Low-time complexity budget–deadline constrained workflow scheduling on heterogeneous resources*
- **Venue:** Future Generation Computer Systems 55 (2016) 29–40
- **DOI:** `10.1016/j.future.2015.07.021`
- **Primary source audited:** complete user-supplied paper PDF

## Original scheduling problem

Given a workflow DAG, a bounded heterogeneous processor set, a user deadline, and a user budget, DBCS seeks any schedule map satisfying both constraints. The paper explicitly states that the formulation has no additional optimization objective: any schedule satisfying both QoS constraints is a plausible solution.

DBCS is a one-pass list heuristic. Its cost control is hard: assignments are restricted so the budget cannot be exceeded when the initial budget is at least the cheapest lower bound. Its task sub-deadline is soft: the scheduler may select a processor finishing after the task sub-deadline when necessary. If the completed map misses the workflow deadline, the paper counts the run as a planning failure and reports no schedule.

## Original infrastructure model

- Bounded set `P` of heterogeneous processors/resources.
- Each processor has execution capability and a price per time unit.
- Cost is charged for effective task execution time in the DBCS model.
- Processor capacity is serial: no processor executes more than one task at a time.
- Idle schedule slots that can accommodate the current task are considered when computing candidate finish times.
- Communication uses average bandwidth `B` and average latency `L` for graph-level quantities.
- Actual same-processor communication time is zero.
- Transfer/storage monetary costs are set to zero for the experiments.
- The SimGrid experiments use a bounded multi-port network model; the analytical DBCS policy itself is expressed through the communication-time quantity `C(i->j)`.

## Original workflow model

- DAG `G = <T,E,Data>`.
- Exactly one entry and one exit task are assumed; dummy zero-cost/time tasks are added when required.
- `ET(t_i,p_j)` is processor-specific execution time.
- `Cost(t_i,p_j) = EC + TC + SC`; in the experiments `TC=0` and `SC=0`, so task monetary cost is execution cost.
- `EST`/`EFT` obey precedence, communication arrival, processor availability, and idle-slot insertion.

## Task priority rule

DBCS uses HEFT upward rank, Eq. (10):

`ranku(t_i) = avg_ET(t_i) + max_{child in succ(i)}(C(i->child) + ranku(child))`.

At every scheduling step the next task is the **ready** task with highest `ranku`.

## Budget handling

For each task:

- `Costmin(t)` = minimum execution cost across all processors.
- `Costmax(t)` = maximum execution cost across all processors.
- `Costcheapest = sum_t Costmin(t)` is the application cost lower bound.

If `BUDGETuser < Costcheapest`, Algorithm 1 returns no possible schedule.

Initial spare budget:

`DeltaCost = BUDGETuser - Costcheapest`.

After assigning current task `t` to the selected processor, Eq. (9):

`DeltaCost <- DeltaCost - (AC(t) - Costmin(t))`.

Cost limit for current task, Eq. (11):

`CL(t) = Costmin(t) + DeltaCost`.

The admissible processor set is all processors whose task cost is at most `CL(t)`. This makes the budget limit hard.

For Eq. (16), the paper describes:

- `BudgetUnconsumed` as the budget not yet consumed by already assigned tasks;
- `CostCheapest` as the cheapest execution cost of the currently unscheduled tasks.

Thus before assigning the current task:

`BudgetUnconsumed = BUDGETuser - sum(actual cost of assigned tasks)`

and

`CostCheapestRemaining = sum(Costmin(t) for unscheduled tasks)`.

This is consistent with the invariant

`DeltaCost = BudgetUnconsumed - CostCheapestRemaining`.

## Deadline handling

DBCS recursively assigns a soft sub-deadline `DL` from the exit toward the entry. Eq. (12):

`DL(t) = min_{child in succ(t)} [DL(child) - C(t->child) - ETmin(child)]`.

For the exit task:

`DL(exit) = DEADLINE`.

`ETmin(child)` is the minimum execution time of the child across all available processors.

The sub-deadline is explicitly soft. If admissible processors cannot satisfy it, DBCS still selects the processor giving the best time-quality result; when all admissible candidates miss `DL`, Eq. (15) makes `CostQ=0` and the `TimeQ` rule selects the earliest-finishing admissible processor.

## Resource-selection rule

For the current task, compute candidate finish times on **all** processors, including feasible idle insertion slots.

Definitions from the paper:

- `FTmin(t)` / `FTmax(t)`: minimum / maximum candidate finish time over all processors.
- `Costmin(t)` / `Costmax(t)`: minimum / maximum task cost over all processors.
- `Costbest(t)`: task cost on the processor producing the lowest finish time.
- `Omega = 1` when `FT(t,p) < DL(t)`, otherwise `0` — Eq. (15).

Time quality, Eq. (13):

`TimeQ(t,p) = (Omega * DL(t) - FT(t,p)) / (FTmax(t) - FTmin(t))`.

Cost quality, Eq. (14):

`CostQ(t,p) = ((Costbest(t) - Cost(t,p)) / (Costmax(t) - Costmin(t))) * Omega`.

Final processor quality, Eq. (16):

`Q(t,p) = TimeQ(t,p) + CostQ(t,p) * CostCheapestRemaining / BudgetUnconsumed`.

Among processors satisfying `Cost(t,p) <= CL(t)`, choose the processor with maximum `Q`.

## Cost model

The original model uses execution duration times price per time unit. Transfer and storage monetary cost are zero in the reported experiments. The IFC adapter uses the frozen `compute_cost_ncu[task][resource]` matrix, already materialized from the benchmark's resource prices and execution times. No network monetary cost is introduced.

All budget arithmetic and quality ratios involving cost use exact integers/rational arithmetic; binary floating point is not required.

## Communication model

The paper defines average communication as `L + data/B` for graph-level calculations and zero communication for tasks mapped to the same processor. The simulator also supports shared-bandwidth effects.

The IFC benchmark has route-specific communication across IoT, fog, and cloud tiers and does not expose the paper's single average-bandwidth/latency platform model. Adaptation:

- use the pinned Dataset route-aware average communication for `ranku` and recursive `DL`;
- use the pinned Dataset exact source-resource/target-resource route time for candidate `EST/EFT`;
- same-resource communication remains zero;
- do not add an independent network-contention simulator inside DBCS, because final cross-algorithm scheduling semantics belong to Dataset.

## Energy model

DBCS has no energy objective or energy term. IFC compute/network energy is measured only after the decision by the common evaluator and must not influence DBCS choices.

## Initialization

1. Build graph and task/resource cost/time summaries.
2. Compute `Costcheapest`; reject the input if budget is below it.
3. Initialize `DeltaCost = budget - Costcheapest`.
4. Compute HEFT `ranku`.
5. Compute recursive `DL` values.
6. Start with no assigned tasks and empty processor interval schedules.

## Constraint-repair rule

None. DBCS is forward-only and does not roll back or repair prior assignments.

## Tie-breaking and undefined normalization cases

The paper does not specify ties for equal upward rank, equal candidate finish time used to define `Costbest`, or equal final `Q`.

Deterministic IFC adaptations:

- equal ready-task rank: lexicographic `task_id`;
- equal earliest finish for `Costbest`: lower task cost, then `resource_id`;
- equal `Q`: lower finish time, then lower task cost, then `resource_id`.

The paper also does not specify the zero-denominator cases `FTmax == FTmin` or `Costmax == Costmin`. The IFC totalization uses a zero contribution from the corresponding normalized dimension because that dimension contains no discriminatory information across processors. Occurrence counts are retained in `algorithm_internal_statistics`.

## Termination / stopping condition

Terminate after every workflow task has been assigned once. The paper then treats a deadline-missing map as a failed planning attempt.

For benchmark observability, the IFC adapter still returns the completed mapping to the common evaluator even when its internal DBCS timing model predicts a deadline miss. This allows uniform metric recording and `joint_feasible=false`; it does not alter any mapping decision.

## Population / iteration parameters

Not applicable. DBCS is deterministic and non-population-based.

## Original complexity claim

The paper derives:

`O(n*p + n(n*p + p)) = O(n^2*p)`

for `n` tasks and `p` processors. The IFC adapter preserves the same one-pass list structure, but route-aware communication derivation can add benchmark-specific work relative to the paper's average-bandwidth abstraction, so the paper complexity is reported as the original claim rather than asserted unqualified for all IFC internals.

## IFC adaptation mapping

| Original paper assumption | IFC treatment |
| --- | --- |
| Bounded heterogeneous processors | Use all materialized IoT, fog, and cloud execution slots as the bounded heterogeneous resource set |
| Every task can execute on every processor | IFC v1 exposes a complete execution matrix; use every materialized resource |
| Per-time-unit execution price | Use exact frozen `compute_cost_ncu[task][resource]` |
| Zero transfer/storage monetary cost | Matches IFC v1: no network monetary charge is added |
| Average `B`/`L` communication for ranking/deadlines | Use route-aware average communication from pinned Dataset primitives |
| Same-processor communication is zero | Preserve exactly |
| Idle slots considered for FT | Reuse Dataset's pinned insertion candidate primitive |
| Single entry/exit, dummy tasks when necessary | Do not mutate the public DAG; multiple sinks are treated as connecting to an implicit zero-time dummy exit, hence each sink receives workflow deadline |
| No energy objective | Energy excluded from policy; evaluator reports it afterward |
| Deadline-missing completed map is discarded | Preserve mapping policy but retain the map for benchmark measurement; record internal paper-success diagnostic |
| Undefined equal-range normalization | Zero contribution for the non-discriminating dimension; count occurrences |
| Unspecified ties | Deterministic rank/finish/cost/resource-ID rules |

## Faithfulness classification

**MINOR IFC ADAPTATION**

The DBCS task priority, hard spare-budget mechanism, admissible-processor filtering, recursive soft sub-deadline, `TimeQ`, `CostQ`, final `Q`, idle-slot-aware selection, and one-pass control flow are preserved. Adaptations are limited to the IFC route-specific network, deterministic totalization of unspecified ties/zero ranges, implicit handling of multiple sinks, and benchmark-wide retention/evaluation of failed maps.
